目的：保存我们在设计、实现、诊断和验收 Agent 时犯过的错误，以及有效或失败的解决办法。记录服务于实际修复和设计学习，不是新的架构、审批 Gate 或完整历史阅读要求。

## 维护约定

- 后续 Agent 故障调查、修复、方案撤回、复发或真实任务验收，在同一 changeset 更新相关条目。未修复也要记录已知现象、证据与下一步；没有新增事实不写流水账。
- 开始相关工作时只查索引和相关条目。普通 UI/其他工作不要求通读本文件。
- 使用稳定编号 `AE-001` 起；同一因果链优先补充旧条目，不重复创建。新证据推翻旧判断时保留原判断及日期，注明修正依据；错误方案不能被成功结论覆盖掉。
- 每条区分：现象、已确认原因、推测、Model/Harness/Tools 责任、修正办法、验证及未验证范围、可复用原则。Harness 要说明具体职责及其作用。
- 状态分三项记录：**原因**（已确认/部分确认/待查）、**机制**（未修复/候选/工程已验证/复发）、**原任务**（未运行/仍失败/已验证，注明模型、版本、任务范围及证据）。工程已验证不能自动变成原任务已验证。

- 本文件不授予产品变更、模型调用或业务执行权限。更新由正在处理该问题的 Agent 随工作完成，不依赖定时提醒。

### AE-001 — 机制测试通过没有建立真实 coding 基线

- **解决办法及失败尝试：** 保持页面身份、两次命中校验和原生输入确认，移除 PNG 门槛。单改截图选项/重试、尺寸模拟、首次可见状态、子视图或单页后台节流均不足；最终按原生对照关闭该 Windows 启发式，保留网页内遮挡与其他安全边界。
- **验证与状态：** 原因：该环境下已确认；机制：原生单变量对照、开发/打包多页点击计数、字段和截图专项通过；原任务：真实模型业务验收未运行。功耗未测；不是全部历史失败的统一解释，完整 PreMerge 缺口见交付。
- **原则：** 命令派发成功必须与实际页面事件和结果分开；模拟桌面不能遗漏真正 native host 的行为。
- **证据：** [原生对照、失败尝试与最终边界](../../artifacts/agent-precise-source-observation/DELIVERY.md)。

### AE-012 — 继续工作没有恢复可用额度和操作事实

- **现象与已确认原因：** 旧逻辑仅在上次暂停因为预算耗尽时续额；用户因未验证而暂停后点击继续，四次调用即再次耗尽。旧进程关联与启动事实不足，又诱发重复查启动配置。
- **责任：** Harness.Governance 管理有界资源授权；Continuity 恢复已完成工作、真实状态与未完成义务。
- **解决办法：** 每次明确用户继续开启新的有界时间/token 窗口并持久记录，保留累计历史及任务身份。自动恢复/审批/重试不自行续额；恢复实际工具事实，不自动重放旧启动命令或修改。
- **验证与状态：** 原因：已确认；机制：近额度暂停、重启、同任务继续和不重复写入的开发/打包用例通过；原任务：解题质量未验收。后续数十轮再次耗尽证明预算可用不能代替有效诊断。
- **原则：** 连续性要恢复工作所需条件；增加额度只能修复资源缺口，不能修复错误推理。
- **证据：** [额度诊断与修正](../../artifacts/agent-resume-allowance-packaged/DELIVERY.md)、[后续仍重复消耗的运行](../../artifacts/agent-browser-handoff-packaged/DELIVERY.md)。

### AE-013 — 把单一运行时所有权与单文件集中实现混在一起

- **首次记录：** 2026-09-15；用户阅读源码时提出 runtime 是否都应在一个文件。
- **现象与已确认事实：** 当前工作区 agent_runtime.rs 为 19,430 行，测试模块从第 12,211 行开始，约 7,200 行属于测试区。测试之前仍有约 12,200 行，包含 AgentCoordinator 主循环/恢复、Fast Edit、IDR 接入、MCP 激活、插件注册、Artifact 操作与完成验证。Model、Tools、Browser、work_state 等已有外部模块，因此不能说全部 Agent 都在这个文件里。
- **原因与责任：** Harness composition 的物理职责集中已确认。为何历次扩展没有及时拆分尚未做 Git 历史归因；不能把“大文件”直接当作原业务失败原因。文件组织让独立职责的阅读和审查集中在同一处，这是维护风险判断，实际回归率/修改成本未测量。
- **解决办法（建议，未实施）：** 保留一个 Coordinator、既有状态与执行权限所有权，按真实职责逐步提取插件/MCP 接入、Artifact 执行、恢复、验证与策略模块。主循环保留调用顺序和状态转换，细节通过明确接口调用；测试可按职责组织。每一步保持行为并执行受影响回归，不为缩短文件新建平行 Runtime 或重写全系统。
- **验证与状态：** 原因：静态结构已确认、失败因果未证明；机制：未重构；原任务：本条不证明 coding 任务质量改善。本次仅源码结构检查，没有运行产品测试或真实模型。Rust 将单元测试写在同文件本身不是错误，移动测试也不能解决职责耦合。
- **原则：** 单一权威和多模块实现可以同时成立。模块划分以职责、依赖与可验证性为依据，没有通用行数阈值，也不能从文件数量推断 Agent 智能水平。
- **证据：** [当前 Coordinator 源码](../../crates/fielora-core/src/agent_runtime.rs)、[已有工作状态模块](../../crates/fielora-core/src/agent_work_state.rs)、[架构职责与单一执行链](../architecture/FIELORA_V0.1_AGENT_ARCHITECTURE_SPEC.md)。开源结构对照：[OpenCode processor](https://raw.githubusercontent.com/anomalyco/opencode/dev/packages/opencode/src/session/processor.ts) 与 [compaction](https://raw.githubusercontent.com/anomalyco/opencode/dev/packages/opencode/src/session/compaction.ts) 分文件，[OpenHands SDK](https://github.com/OpenHands/software-agent-sdk) 分 SDK、Tools、Workspace、Agent Server 包；2026-09-15 查看，外部主分支会变化。这些是组织方式示例，不是性能优越性证明。

### AE-014 — 任务用量与当前模型必须来自实际调用身份

- **现象与确认原因：** 设置没有任务用量汇总。主循环与 Fast Edit 的 MODEL_COMPLETED 已保存 usage，但 delegate_readonly 的同类事件只写 text/tool count，丢掉已返回的 usage。Provider 的输入/输出可空，失败或取消的调用也可能没有可持久化用量，不能把零与未知混为一谈。
- **责任：** Model adapters 归一化服务回执；Harness.Continuity 保存 Run 固定 provider/model 与真实调用回执；设置是该历史的只读产品投影。Composer 当前选择是下次发送的配置，不拥有旧任务归属。
- **办法：** StorageWorker 新增 owner-scoped 分页汇总，重读不可变事件而非 UI 累加计数，日期按回执时间。补齐子任务 usage 字段；主任务与子任务分别展示，按模型/日汇总总消耗。当前活动 Run 和 Composer 下次模型分开显示；单价只是本地估算偏好，币种不混加。没有第二套 Runtime、用量数据库或安全权限。
- **验证与状态：** 原因已确认；聚合、模型/owner/日期隔离、零值与缺失、分页不截断总计、重复读取幂等通过定向测试。桌面、重启与最终 Lane 结果见 [专项交付](../../artifacts/model-usage-statistics/DELIVERY.md)。未调用真实付费 Provider；未补回服务未返回的流式/中断用量或历史子任务缺失数据，不宣称与服务商账单精确一致。
- **原则：** 用量归账绑定执行时的身份；UI 配置变化不能重命名历史事实。缺失遥测必须可见，估算不能冒充账单。
