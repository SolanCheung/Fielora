User flow: compare source paths explicitly supplied in the task with the active project, preserve its APIs, then verify the requested adaptation. The new package was in use.

Change: reuse existing read/search/list/stat tools for absolute paths inside explicitly named existing local reference paths. Harness derives the bounded scope from the original task, never from a model tool argument, tool output, project file or work plan. Relative paths continue to mean the target project. Receipts carry absolute source identity and reference scope. Writes, commands, Git and capability authority remain target-scoped. No schema or parallel permission runtime is added.

Boundary: exact file references stay exact. A named source directory grants read-only access to its nearest existing Git/package project boundary (bounded ancestor discovery), so controller references to templates and translations remain readable. Without a project boundary, keep the exact directory. The explicitly named directory remains the comparison coverage anchor: reading an unrelated dependency does not satisfy it. No filesystem roots, UNC/device paths, parent traversal, protected credential/Git paths, or symlink escape. Filesystem canonicalization and existing size, UTF-8 and output limits apply. Reference reads do not count as target mutation or goal verification. On completion the existing loop checks actual nonempty source reads; this is an evidence prerequisite for comparison, not proof of semantic equivalence.

Recovery: derive scope again from the same durable original task on resume. Keep unread reference obligations in model context. Server process liveness or a failed socket probe must not be presented as compilation progress. Preserve existing resource caps; do not compensate by raising budget.

Validation: isolated two-project tests must read/search the named reference, reject siblings/parents/writes/protected paths, distinguish same relative filenames, and retain missing-read obligations after failed calls.
