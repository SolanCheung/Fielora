# Agent browser verification — Change Impact

Date: 2026-09-10. Authorized by the user's “开始吧”.

Flow: an Agent opens the target application's HTTP(S) page in the existing right workspace, observes the rendered dialog, operates observed controls, checks explicit acceptance cases, and reports only receipt-backed results. Validation uses an isolated local invoice-dialog fixture with incorrect translated labels, partial payments and an overpayment case; production finance data is untouched.

Tools: extend the existing built-in tool catalog and Electron BrowserRuntime. A bounded browser_server tool reuses WorkspaceRuntime terminal processes: structured literal Node/npm/pnpm/yarn arguments, trusted Project root, one server per run/four total, bounded output, explicit stop, owned process-tree cleanup on Core restart/app exit. Server startup is not verification. Core sends approved, run-bound requests through the existing parent FIPC channel; only Main can answer. Remote pages receive no preload, Node, FIPC, filesystem or arbitrary-script capability. Actions use bounded observed element references in a fixed isolated-world adapter; navigation/snapshot identity is checked. Agent pages belong to their run, and cannot silently operate a user's other page. Existing permission policy covers network/page side effects. Timeouts, cancellation, stale pages and detached controls fail closed; no automatic replay of an uncertain click.

Harness: retain existing execution/approval/storage and VerificationReceipt. An explicit acceptance plan and per-case browser assertions are stored in tool receipts, tied to the current workspace revision. Opening a page or passing a build cannot substitute for UI assertions. Missing cases, failed assertions, later edits and a changed plan invalidate completion. Model-generated acceptance criteria are not a proof of exhaustive requirement coverage; the report must state the actual checks and remaining limits.

No migration or second Runtime/Permission/Evidence store. Main-only completion IPC is additive and is not exposed through preload. Screenshot evidence reuses existing storage. Rollback removes the additive tool/host path; historical receipts remain readable. Validate unit security/staleness/coverage tests, real Electron/Core/model-fixture flow, existing browser security and Agent recovery regressions, Cross lane and packaged smoke. Real provider quality and authenticated production transactions remain unverified.
