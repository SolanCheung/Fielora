# Fielora Competitive Boundaries

## 1. 不用“AI Browser 功能数量”竞争

以下视为 Foundation / Commodity：AI 问网页、页面总结、搜索、划词问答、截图问答、跨 Tab Context、Vertical Tabs、Tab Group、Split View、Browser Agent、网页点击/表单、Multi-LLM、Connected Apps、MCP/WebMCP、Workflow/Shortcut 保存、AI 收藏/笔记。

这些能力可以拥有，但不能解释“为什么 Fielora 必须存在”。

## 2. Fielora 应竞争的层

- **Continuity**：恢复工作现场，而不是只恢复 Tab。
- **Lifecycle**：Idea / Requirement / Implementation / Test / Result 属于同一持续链。
- **Field**：数字工作的一级单位从 App / Tab / Chat 变成 Field。
- **Dynamic Surface**：Fielora 根据当前工作状态组织工作面。
- **Promotion**：Capture / Idea / Field / Requirement 有自然成长路径。
- **Work Lineage**：能追溯为什么产生需求、哪个调研支持决定、哪段代码实现、哪个测试验证。
- **Human-Agent Shared State**：AI 在同一 Field State 内工作。
- **Professional Tool Orchestration**：不复制最专业工具，而是放回完整工作上下文。
- **Personal Steward**：长期从真实工作和生活状态中成长。

## 3. 视觉去同质化

Browse 可以像优秀浏览器，不为不同破坏成熟习惯。

Field 必须脱离 `左 Tab + 中网页 + 右 AI`，进入 `Current Goal / Focus → Dynamic Working Surface`。Browser 只是 Surface 之一。

## 4. 审核问题

1. 遮住 Fielora Logo 后，这是不是仍然只是 Chrome / Tabbit / 豆包 + AI Sidebar？如果是，继续改。
2. 页面是否因为系统内部“知道很多”而把所有能力常驻展示？如果是，继续删。
3. 当前最重要工作对象是否占绝对视觉主导？如果不是，重新编排。
